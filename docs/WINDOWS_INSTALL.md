# Bordena W 1.0 — Windows x64

Обновлено 14.11.2026. Машинная версия 1.0.0, identifier team.chopik.bordena.
Локальный подписанный кандидат существует; наличие исходников на GitHub не означает публичный Stable.
Актуальные результаты: [отчёт](BORDENA_W10_RELEASE_REPORT.md), [checklist](BORDENA_W10_RELEASE_CHECKLIST.md).
Прежняя инструкция сохранена без изменений в releases/WINDOWS_INSTALL-before-W1.0.md.

## Установка

Основной файл — Bordena-W1.0-Windows-x64-Setup.exe. NSIS устанавливает приложение
для текущего пользователя и создаёт ярлык в меню «Пуск». Node, Rust и исходники
пользователю не нужны. Официальный источник после закрытия релизных gates:
https://github.com/chopik-team/Bordena/releases.

WebView2: downloadBootstrapper. Если Runtime уже установлен, повторная загрузка
не требуется. Если отсутствует, первоначальная установка Runtime требует интернет.
После установки основная работа Bordena — офлайн. Отдельный offlineInstaller
сейчас не выпускается по решению владельца. Нельзя удалять Runtime с основной
машины пользователя ради этой проверки; нужен изолированный тестовый Windows.

Подписи installer/metadata проверяются закреплённым ключом доставки CHOPIK.
Windows Authenticode отсутствует: издатель CHOPIK Team в свойствах/реестре
не заменяет сертификат Windows. Возможен SmartScreen. Инструкция не предлагает
обходить защитные предупреждения.

## Обновление и восстановление

CHOPIK Launcher использует официальный GitHub источник и проверяет metadata,
подпись installer, размер и SHA-256 до запуска NSIS. Сначала закрывается Bordena.
Обновление использует /UPDATE, запрещает downgrade и конкурирующие операции.
Данные досок хранятся отдельно от каталога программы. Для ручной страховки
экспортируйте проверенную копию через настройки Bordena на другой диск.

При ошибке не удаляйте профиль и не импортируйте данные поверх него вслепую.
Launcher сохраняет предыдущие программные файлы в своём cache/Bordena-recovery/
before-update-* и сообщает точный путь, если NSIS завершился с ошибкой.
Это копия файлов программы, а не транзакционный rollback реестра Windows.
Если действующий EXE сохранился, запустите его и проверьте проекты. Если программные
файлы повреждены, сохраните журналы и профиль, закройте процессы, переустановите
проверенный подписанный installer той же или более новой версии в прежний путь
и повторно проверьте регистрацию, версию и проекты. Такая переустановка должна
восстановить регистрацию; простое копирование EXE её не восстанавливает.
Возвращать старую версию после частичного обновления реестра автоматически нельзя:
при запрете downgrade восстановите совместимую версию проверенным installer.
Полный аварийный rollback после OS interruption/disk-full ещё PENDING.

## Среда разработки и QA

Разработка — dev.bat, локальный release — Bordena.bat. Node 24.19.0,
pnpm 11.25.0, Rust 1.99.1 MSVC, C++ tools/SDK, WebView2. Инструменты не входят
в пользовательский дистрибутив. После установки зависимостей по frozen lockfile:

- pnpm check:version; pnpm check:i18n
- pnpm type-check; pnpm lint; pnpm test
- cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml
- pnpm build:windows

QA — только отдельные .tools/qa-* профили и team.chopik.bordena.release-qa.
GitHub windows-2022 — Windows Server с предустановленными компонентами;
его успешный CI не заменяет чистую Windows 10/11.
Новые пользовательские скриншоты в этой итерации не создаются.
