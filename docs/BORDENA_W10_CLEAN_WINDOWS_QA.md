# W 1.0 — оставшиеся проверки Windows

14.11.2026. Это протокол, не результаты выполненных испытаний.
Windows 10 x64, Windows 11 x64 и WebView2-absent сейчас **PENDING**.
GitHub windows-2022 — Windows Server, не чистая клиентская Windows.

## Условия

Использовать разрешённую VM/отдельную тестовую машину. Сохранить checkpoint чистой
ОС и повторяемые снимки до установки и до обновления. Не использовать рабочие
профили пользователя. Зафиксировать OS build, наличие Runtime, installer SHA-256,
source commit, логи NSIS, пути программы/данных, результат каждого шага.
Убедиться, что восстановление VM checkpoint действительно работает.

## Матрица для каждой ОС

1. Проверить закреплённым ключом точные metadata и installer; сверить SHA256SUMS.
2. Установить для обычного пользователя. Проверить завершение NSIS, ярлык «Пуск»,
   W 1.0/1.0.0, publisher и повторный запуск. Не обходить SmartScreen средствами QA.
3. Создать/импортировать QA-проекты с вложениями, настройками и связями. Сделать
   внешнюю резервную копию, сверить её чтением и хэшами, сохранить снимок данных.
4. Проверить повторную установку, обновление через существующий Launcher и staging
   1.0.1, повторный запуск; сверить пользовательские поля и байты вложений/backup.
   Нельзя публиковать тестовую 1.0.1 как Stable.
5. Удалить/переустановить приложение, повторить проверку данных и ярлыков.
6. Отдельно проверить запуск с отключённой сетью после установки.

## WebView2

На checkpoint без Runtime проверить обычный downloadBootstrapper с интернетом:
загрузку, завершение установки Runtime, запуск Bordena. На отдельном checkpoint
без Runtime отключить сеть и проверить понятный отказ и сохранность данных.
На checkpoint с Runtime проверить работу установщика без сети.
Не удалять Runtime с основной машины. OfflineInstaller не добавляется по решению
владельца: стандартный небольшой Setup остаётся основным вариантом.

## Отказы

Проверенные на существующей Windows 11 isolated QA сценарии перечислены в отчёте:
подпись/checksum/размер/архитектура, offline/HTTP/обрыв, запущенный EXE,
повтор/downgrade, mutex и смена версии после первой проверки, NSIS Cancel до
копирования, контролируемый installer exit 7. Это не доказательство аварийного
восстановления после частичной записи.

Для disk-full и аварийного прерывания использовать отдельный ограниченный диск VM
и checkpoint, не физический диск пользователя. Проверить отказ при загрузке,
создании recovery snapshot и записи installer; прервать NSIS в заранее выбранной
безопасной точке тестовой VM. Проверить фактическую пригодность приложения,
регистрацию, сохранность проектов и восстановление. Записать точные шаги и хэши.
До реального испытания эти пункты остаются PENDING; автоматический rollback
реестра не реализован. Ручной способ восстановления — WINDOWS_INSTALL.md.

## GitHub и Launcher

Stable v1.0.0 допускается только после обязательных gates. После публикации
скачать настоящие assets независимо от локальной папки и авторизованной сессии;
проверить HTTPS, публичный доступ, размер/SHA-256 и обе закреплённые подписи.
Существующая публично доступная версия Launcher должна получить этот же релиз,
установить, обнаружить и запустить его. Локальная integration-сборка Launcher и
скачивание GitHub Actions artifact не заменяют этот пользовательский сценарий.

До получения фактических результатов: **PUBLIC RELEASED — PENDING**.
